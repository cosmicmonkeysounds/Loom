# K-11 device check — redeem throttle + door-rush limits (≈ 6 min)

Use a **rehearsal** (the project's preview event), never the live show.

1. **Set the night's env on the VPS** (`.env` next to `docker-compose.yml`):
   ```
   LOOM_RL_RESOLVE=600
   LOOM_RL_REGISTER=400
   LOOM_RL_LOGIN_FAILURES=100/300
   ```
   (`LOOM_RL_REDEEM_MISSES` stays blank = 8 a minute per guest.) Then
   `docker compose up -d loom` so the server picks them up.
2. Run → Start rehearsal. Note the **event code**.
3. **Door rush** from one laptop (one IP, like the house Wi-Fi):
   `node --experimental-strip-types scripts/accept/K-11.ts rush 40 --base https://app.mapsandducks.com --code <EVENT CODE>`
   → `40 × 200`, PASS. (Without the env, expect `20 × 200, 20 × 429`.)
4. **Redeem throttle** (script):
   `… K-11.ts redeem --base … --code …` → `200 ×8 then 429`, PASS.
5. **Redeem throttle on a phone** (1 min): join the rehearsal, open the
   pinned **Codex** room, type 9 wrong codes fast. The first 8 each land as a miss
   (the story's wrong-code reply); the 9th does nothing (the play app
   currently swallows the 429 silently). In Run → Log only 8
   `codexMissed` lines appear. Wait a minute → codes work again.
6. Run → Restart the rehearsal to clear the `K11 Probe …` guests.

Unit proof (no device): `core/test/codex.test.ts` → *the 9th wrong code…*,
`core/test/server-security.test.ts` → *door-rush limits (LOOM_RL_*)*.
