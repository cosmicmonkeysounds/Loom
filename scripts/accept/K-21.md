# K-21 device check — the cue sheet, from the second director's laptop (≈ 8 min)

Use a **rehearsal** (the project's preview event), never the live show.
Needs master deployed to https://app.mapsandducks.com first.

1. **Membership** (owner, 1 min): in the editor launchpad open the show
   project → **Share** → add the second director's email. They get an
   email (or copy the invite link to them).
2. **Their sign-in** (second director, own laptop, 1 min): open
   `https://app.mapsandducks.com/edit/`, sign in / sign up **with their own
   account**, open the project under *Shared with you*.
3. Owner: **Run → Start rehearsal** (or keep the one already running).
   Join it from one phone as a guest so there is somebody to move.
4. Second director: **Run → Director**. The **Cue sheet** is the first
   panel:
   - rows read `1 C1/V1 📣 Call everyone to the Desktop`, `V2 …`, `V3 …`,
     `Clippy 2/X …`, `V4/V5 …`, `C2 …`, `V6 …` in that order, then the
     uncoded cues; row 1 is tagged **NEXT**;
   - the header shows `phase: …` (the story's `Night.phase`).
5. Second director clicks, one at a time, **C1/V1 → V2 → V3 → Clippy 2/X
   → V4/V5 → C2 → V6**. After each click:
   - that row turns amber with **LAST**, the following row gets **NEXT**,
     earlier ones show a ✓;
   - `phase:` changes (e.g. `desktop` → `bingo` → `bingo_results` →
     `introduced` → `hunt_1` → …);
   - the owner's Run → Director shows the **same LAST row** within a
     second (both read the server's log).
6. Type `printer` in the filter → only the two printer cues remain.
   Clear it.
7. **Reload** the second director's tab: LAST/✓ marks come back as they
   were (they are rebuilt from the server, not the browser).
8. Run → Restart the rehearsal to clear it.

Pass = steps 4–7 hold on the second director's own account.

Unit proof (no device): `core/test/views.test.ts` → *cue sheet state
(K-21)* + *the show's cue sheet (K-21)*;
`editor/src/components/cockpit/cue-sheet.test.ts`.
